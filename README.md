# 🧩 brAInly – Learning Assistant for Children with Autism

**brAInly** is a mobile-responsive web application prototype designed to support the **education, communication, and daily living skills of children with autism spectrum disorder (ASD).**

Developed as part of the **Microsoft AI Innovators Summer Internship Program**, brAInly was created by a 4-person student team as a **Minimum Viable Product (MVP)** within approximately one month.

> 🎯 **Project Goal:** To support learning, daily routines, social communication, and progress tracking through an accessible and visual digital platform.

## 🌟 Features

### 📚 Learning Cards

Visual and educational cards designed to support learning through images and simple interactions.

### 💬 Social Scenarios

Interactive examples of situations that children may encounter in everyday social life.

### 🗓️ Daily Routine Tracking

Users can mark completed daily tasks and keep track of their routines.

### 👤 Child Profile

A profile section for displaying basic user information.

### 📊 Progress Tracking

The application tracks:

* Correct and incorrect answers
* Completed routine tasks
* Overall activity performance

### 🤖 Smart Recommendations

The current MVP provides **rule-based personalized recommendations** based on user activity and performance.

> **Note:** The current version does not use a real AI model or external AI API. Real AI integration is planned for future versions.

## 💾 Data Management

The current MVP operates entirely on the client side.

User activity data is stored using the browser's **LocalStorage**, allowing information such as completed routines and activity results to persist after refreshing the page.

No external database is required for the current MVP.

## ⚠️ Current MVP Scope

brAInly is currently a **prototype/MVP**. Some advanced features are simulated for demonstration purposes.

### ✅ Currently Working

* Daily routine completion
* Learning cards
* Correct/incorrect answer system
* Social scenarios
* Child profile
* Progress calculation
* Local data persistence

### 🔄 Simulated / Planned

* User authentication
* AI-powered recommendations
* Firebase / Firestore database
* Real AI model or API integration
* Demo user account

These limitations are intentional within the current MVP scope.

## 📈 Development Process

The project was developed in four stages.

### Week 1 – Planning & Design

* Defined project scope
* Determined core features
* Created application flow
* Designed logo and color palette
* Prepared educational content

### Week 2 – Prototype Development

* Developed login and home screens
* Created profile, routine, learning cards and social scenarios
* Implemented page navigation

### Week 3 – Data & AI

* Implemented routine completion
* Added correct/incorrect answer system
* Created progress tracking
* Developed rule-based recommendations
* Added demo data

### Week 4 – Testing & Presentation

* Fixed bugs
* Improved the user interface
* Tested the MVP
* Prepared the final demo and presentation
